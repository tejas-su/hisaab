Your own categories proposal

Case study 22, drawn. The 8 tiles never move. Up to 4 categories of your own fill a third row after them, oldest first. You make one at the moment you need it: in the Add tray, tap the New tile in row 3, after the 8, type or tap a name, and Save in Petrol makes the category and saves the entry in one go. The icon comes from the name; changing it is optional. Settings › Categories renames any category and hides your own, with Undo; a hidden category's entries stay. The usual path, Add → digits → Next → tile, gains no tap. Today is Mon 26 Oct 2026, and the amount is ₹250.

Departs from SPEC BR-11 ("Order and count are fixed in v1") and adds a control to the Add tray (FR-AD-5). Both need your yes and a DECISIONS row before this is built.

Try it

Tap New category, type petrol, kirana, Riya school or food, and watch the icon line and the key. Save, then press Add on Home to see your tile in row 3. Settings on Home opens Categories, where you can rename, change the icon, or hide one and undo.

1. The Add tray, before you have any

Chosen: the tile (option B below). A New tile sits in the first free slot after the 8, under a quiet "Your own" rule: dashed ink2 outline, no fill, so it reads as a place for a category rather than one. It never takes Other's slot; Other stays the catch-all, and the 8th slot keeps saving when tapped from habit (D13). The tray is one row taller from day one. No long-press: nobody would find it, and it fails WCAG 2.5.1. Spent only; the Got tray stays as it is.

2. Name it

The grid gives way to a name step inside the same tray; ₹250 stays in the title. Six name chips cover the gaps the IA review found (groceries apart from eating out, kids, family, pets, personal care) plus Petrol; they narrow as you type. The icon line says where the icon came from, in words. The key says exactly what will happen: Save in Petrol makes the category and saves the ₹250 there, then the tray closes as it always does (flash, drop, drain, success haptic).

3. Change the icon (optional)

51 icons, every one with a word under it, in six groups: food and drink, treats and habits, getting around, home and family, care and giving, things and fun. The list scrolls inside the tray; the icon the name picked sits where it always does, already ticked. No search. A pick fills ink2 with a tick, as a picked chip does (D89), and goes back to the name step without saving.

5. Settings › Categories

This also builds FR-SE-2, which is specified but unbuilt. The 8 can be renamed and given a new icon but never hidden. Your own can also be hidden: archived = 1, Undo, no dialog (D4). Its entries keep its name and icon in Spends, filters and past cycles. Typing a hidden category's name brings it back instead of making a copy. A renamed built-in shows its new name on old entries too, and the sheet says how many.

Icons

A curated 51, not the whole library. The free stroke-rounded set has about 6,000 icons and no keywords; this picks the ones that look like daily spends and habits, so a smoker can track cigarettes and an occasional drinker can track drinks without hunting. Every glyph here is the real Hugeicons path from hugeicons 1.2.0, checked by eye: Book02 is really a code file and Fuel a jerry can, so Book03 and PetrolPump are used. The name picks the icon as you type: the first entry with a word in the name wins, top to bottom; with no match it's Tag. Hindi and Hinglish words are included because people type them in Latin script. Habit words are plain and never judged: no warnings, no "quit" nudges.

Storage: the database stores only the app-owned key in the first column (icon_key = 'cigarettes'), never a glyph or a Hugeicons name. AppIcons.byKey in the presentation layer maps key to glyph, as it already does for the 8; an unknown key draws Other. A shipped key is permanent; swapping its glyph later changes only the map. The word table lives in the domain as CategoryIcon.forName(name) → key.

Drawn, because the free set lacks them: Chai (a cutting-chai glass), Paan, Hookah and Auto live in HisaabGlyphs (D48), in Hugeicons' stroke-rounded format: 1.5 stroke, round caps and joins, every point on the 2–22 grid, with curves borrowed from GlassWater, Tea, Keyboard and Motorbike01. Chai replaces the Tea cup, since a stall glass is how chai is bought. They render through AppIcon like every other icon.

Rules

  • Count: the 8 built-in Spent categories, plus up to 4 of your own. Hidden ones don't count toward the 4. Money in and Other income stay fixed.
  • Name: 1–16 characters after trimming (a 72dp tile at 1.5× text fits two lines). Must not match a shown name, ignoring case, including renamed built-ins; that case saves into the existing one. Must not be savings or card bill, the hidden export names (D120, D123).
  • Order: your own keep the order they were made in. Nothing is ever sorted by use (D13).
  • Data: rows in categories with kind = out, no seed key, sort 9–12. A migration may add user_made (or a nullable seed key) so built-ins can't be archived. icon_key holds an app-owned key from the icon table (never glyph data or a Hugeicons name); AppIcons.byKey draws it. A pure CategoryIcon.forName → key in the domain, written test-first like BillIcon.forName, holds the word table.
  • Everywhere else: Spends rows, the entry filter chips, insights, limits, CSV, Ask AI and backup already work per category id and name. Insight #1 skips a category with no previous cycle. Restore must accept categories with no seed key.
  • Privacy: a category name like "Riya school" leaves the phone in the Ask AI export even with notes left out. The preview shows it; design-content should check the switch's wording.

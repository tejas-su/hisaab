The split bar, in three states

The bar always measures against income. Bills are solid, everyday spending is a lighter solid, Saved is an outline, and what's left is the empty track. If spending passes income, the part past the income mark is striped. Striping already means "over" on Where it went, so it means the same thing here.

What each idea is for

1One comparison sentence

It compares spending with the same day of last cycle, using BR-14 #1's day-of-cycle rule (min(k, previous length)). It shows only when the last cycle was fully tracked. The arrow and the words "less" or "more" carry the meaning, with no colour and no grade.

TalkBack: "2,100 rupees less than by this day in September."

2Income split bar

It replaces the grey Spent · Saved · Not logged line (FR-SP-4a). Bills are entries with a recurring_id, so this needs no schema change. Mid-cycle the empty part reads Still free. Once the cycle ends it reads Left over. It shows rupees, not a %.

  • Not logged joins Everyday and is named under the bar when above ₹0.
  • Needs a DECISIONS row: D120 says saves are never in the bars.

TalkBack: "Of 45,000 rupees: bills 8,200, everyday 19,370, saved 1,000, 16,430 still free."

3Rows that explain themselves

One headline names the biggest category. Each row adds its change against last cycle at the same day. A tap opens the 3 biggest entries, with the note, or "No note", and the date, then See Food entries. Order, %, bars and limit hatching are unchanged.

  • BR-14 #1 would repeat the row's change, so it should step aside when the row shows it.
  • A row with one entry (Bills) shows that entry only.

4Last 6 months

It shows spending plus saving per cycle against an income line. The current cycle is drawn as an outline because it isn't finished. It appears only after 2 finished cycles. Tapping a month reads it in words. The summary line counts and never labels: "4 of the last 5", never "your best month".

  • Effort L, so it comes last. It needs I and K for past cycles.

# Decision log

| D1 | 2026-10-26 | **Android only**, Flutter | Focus; the target users are on Android | iOS and web in v1 |
| D2 | 2026-10-26 | **INR only in v1**, but `intl`/gen-l10n, `Money` with a currency code, and `en_IN` formatting from day 1 | Ship simple; avoid a costly migration later | Hard-coded `₹` strings |
| D3 | 2026-10-26 | **The budget cycle follows payday automatically**; a single Settings override sets the month to start on the 1st | Users think in "till salary"; the term "budget period" confuses (SPEC BR-1) | Asking the user at onboarding; calendar month only |
| D4 | 2026-10-26 | **Zero-config defaults**: no category budgets at start (auto-suggested after one cycle), no accounts or wallets, no confirmation dialogs (Undo instead) | "A 5-year-old can use it" | Setup wizards; budgets first |

| D8 | 2026-10-26 | **Calm monochrome + one signal colour**, marigold `#FFB020`, meaning "today / act" | Client choice; the Braun ET66 → Apple lineage; colour used only when meaningful | Warm clay palette; bright playful palette |

| D12 | 2026-10-26 | **Whole rupees only** in entry and display; stored as paise | Low-literacy research: decimal errors dominate; consistent precision builds trust | A decimal key |
| D13 | 2026-10-26 | **Fixed positions**: categories, keypad (phone layout) and dock never reorder | UPI users memorise positions; PhonePe 2025 backlash | Most-used-first ordering |

| D17 | 2026-10-26 | Team rules ported from `melento-nocode-flutter`, with **Cubit-first**, **get_it at the composition root only**, `equatable` instead of `freezed`, and `fpdart` for errors | Same habits as the team, sized for a small offline app | Bloc everywhere; no DI framework |
| D18 | 2026-10-26 | Feature-first layout with a shared **`ledger`** feature | UI features share money data without putting feature logic in `core/` | A global `data/` and `domain/` layer |
| D19 | 2026-10-26 | Forecasts rounded to ₹100 and prefixed "about"; pace excludes recurring bills | Honest about uncertainty; scheduled bills aren't "pace" (SPEC BR-7) | Exact-rupee forecasts |
| D20 | 2026-10-26 | **One `settings` key-value table, split by owner:** ledger owns money keys (`currency`, `month_start`, `keep_aside_minor`), the settings feature owns app preferences (`theme_mode`, `onboarding_done`, `onboarding_draft`). The pay rule lives on the income recurring row | Each key has exactly one owning repository; no feature logic in `core/` | Separate tables per owner; a core-level preferences store |
| D21 | 2026-10-26 | **No hidden long-press features in v1** (day-block detail, "make this repeat") | Undiscoverable for the target user; recurring bills live in Settings | Long-press shortcuts |
| D22 | 2026-10-26 | **Adaptive layout, no orientation lock**: one pure `AppLayout.resolve` decides single, two-pane (width ≥ 840 dp or a vertical fold) or tabletop arrangements | Android 16 ignores orientation and resizability locks on large screens; foldables and tablets are common | Portrait-only phone layout |
| D23 | 2026-10-26 | **Fonts bundled as assets** (`assets/fonts/`, OFL licences on the licence page); `google_fonts` removed | Offline app; no runtime fetching; one less dependency | `google_fonts` with runtime fetching disabled |
| D24 | 2026-10-26 | **`CalendarDate` value type** for every "day" (UTC-backed maths); `Failure` is an abstract base class, not `sealed` | Removes time-of-day and DST bugs; Dart forbids subclassing a sealed class from another library, so features couldn't add their own failures | `DateTime` at local midnight; a sealed `Failure` |
| D25 | 2026-10-26 | **fpdart throughout**: validators and parsers return `Either<Failure, T>`, I/O returns `TaskEither<Failure, T>`; only programmer errors (e.g. mixing currencies) throw | User request; failures are visible in types | Exceptions for validation |
| D26 | 2026-10-26 | **Weekly pay converts the monthly answer**: weekly salary = monthly × 12 ÷ 52, floored to the rupee | Onboarding asks one question ("each month") for everyone; a second amount question adds a step | Asking the weekly amount separately |
| D27 | 2026-10-26 | **"It changes" records this month's income as one Got entry** dated the 1st, with no salary rule | Home works straight after onboarding instead of showing the no-income card | Discarding the step-1 answer (E10 card at once) |
| D28 | 2026-10-26 | **Onboarding dates everything from this cycle's start**: salary and bills already due this cycle are posted at once | `I`, `S_prev` and `B` match reality for fixed money; typed spending before install stays unknown (SPEC Q6) | Starting from today, which drops this cycle's salary |
| D29 | 2026-10-26 | **On a tabletop fold the Add tray keeps to the lower half**, amount beside keypad | Flutter's modal sheets confine themselves to one side of a fold; the lower half is the flat, touchable one and leaves the hero visible | A full-window tray split at the fold |
| D30 | 2026-10-26 | **`app_en_IN.arb` exists** (empty, inherits `en`) | Without it Flutter resolves `en_IN` to `en`, and amounts lose lakh grouping (₹125,000 instead of ₹1,25,000) | Forcing `Intl.defaultLocale` only |
| D31 | 2026-10-26 | **M1 absorbs `SafeToSpend` and the recurring engine** (start and resume) | The hero and onboarding (FR-ON-5) can't work without them; M2/M3 keep the extras | Placeholder numbers until M3 |
